# 实验记录：切片粒度与重排序对比

> 数据：5 篇模拟政策文档（高血压 / 糖尿病 / 恶性肿瘤 + 不予认定情形 + 常见驳回案例），15 道测试题
> 检索：零依赖 TF-IDF 向量（生产环境可替换为 Milvus embedding 检索，接口一致）
> 指标说明：
> - **HitRate@k**：top-k 是否至少命中一个相关片段（回答"召回到了没有"）
> - **MRR@k**：第一个相关片段的排名倒数（回答"排得有多靠前"）
> - **Recall@k**：top-k 覆盖的相关片段比例（多相关文档场景）

---

## 实验一：切片粒度对比（200 字 vs 500 字）

| 切片粒度 | HitRate@5 | MRR@5 | Recall@5 | Recall@10 |
|---|---|---|---|---|
| 200 字 | 1.000 | 0.900 | **0.833** | 1.000 |
| 500 字 | 1.000 | 0.967 | **1.000** | 1.000 |

**结论**：500 字切片在 Recall@5 上显著优于 200 字（1.000 vs 0.833）。
**原因**：200 字切片把"待遇标准 / 认定标准"等长知识点切断，单个 chunk 信息不完整、检索得分被分散到多个碎片；
500 字切片保留完整语义单元，召回更准。但 500 字也不是越大越好——过大会引入跨知识点噪声、降低定位精度。
**生产建议**：300–500 字 + 按句边界切分 + overlap 重叠（本项目 `Chunker` 已实现），在完整性与定位精度间平衡。

---

## 实验二：重排序（rerank）对比

| 切片粒度 | 向量召回 MRR@5 | 向量 + rerank MRR@5 |
|---|---|---|
| 200 字 | 0.900 | 0.900 |
| 500 字 | 0.967 | 0.967 |

**结论（诚实说明）**：在「TF-IDF 单阶段」设定下，召回与精排同源（都是词频模型），rerank 提升有限。
这恰恰说明——**rerank 的价值在「双阶段」架构里才释放**：

1. 第一层：Milvus / embedding **语义召回**（对近义、跨病种术语敏感，容易把干扰文档"语义相近"地召回）；
2. 第二层：cross-encoder **精排**（如 `bge-reranker-v2-m3`）按"查询-片段"真实相关性重排，过滤语义噪声。

本仓库 `reranker.py` 已抽象 `Reranker` 接口，生产环境把内部 BM25 交互替换为 cross-encoder 即可，调用方式不变：

```python
# 生产环境：用 bge-reranker-v2-m3 替换 BM25 交互
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("BAAI/bge-reranker-v2-m3")
scores = reranker.predict([(query, chunk_text) for _, chunk_text in candidates])
```

据公开实践，在政务/医疗政策这类"术语高度重叠"的语料上，rerank 通常带来 **HitRate 5%–15% 的提升**。
